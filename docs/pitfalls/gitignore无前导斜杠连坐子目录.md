# `.gitignore` 里无前导斜杠的目录规则会连坐所有层级

**首次踩到**：任务 12 / 13

## 现象

为了只忽略"仓库根目录的运行时日志"，在 `.gitignore` 写了 `logs/`。结果 `docs/logs/`——一个八竿子打不着的、需要纳入版本控制的目录——也被静默忽略了。`git status` 里它直接消失，不报错、不提示。

## 原因

`.gitignore` 中**含 `/` 但不在开头**的模式，其 `/` 只是路径分隔符；而 `logs/` 这种"末尾带斜杠、前面无斜杠"的写法表示**匹配任意层级**下名为 `logs` 的目录。要锚定到仓库根，必须写 `/logs/`。

这类坑的危险之处在于**失败是静默的**：文件确实没被跟踪，但没有任何报错，只有主动 `git check-ignore -v <path>` 才能看出是哪条规则命中的。

## 规避

- 想只忽略根目录时，**一律加前导斜杠**：`/logs/`。
- 新增忽略规则后，用 `git check-ignore -v <path>` 验证命中情况，别靠肉眼推断。
- 顺带用 `git check-ignore -v` 反向确认"本该被跟踪的路径确实没被忽略"。

## 本仓实例

`.gitignore` 中最终写作 `/logs/`，并附注释说明前导斜杠不可去。同类风险参见 `docs/logs/index.md` 的说明块。
